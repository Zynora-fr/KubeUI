# Getting help with KubeUI

- **Bug or something not working as documented?** [Open an issue](https://github.com/Zynora-fr/KubeUI/issues/new/choose)
  using the bug report template.
- **"How do I..." / usage questions?** [GitHub Discussions](https://github.com/Zynora-fr/KubeUI/discussions).
- **Feature idea?** Post it in the [Ideas category](https://github.com/Zynora-fr/KubeUI/discussions/categories/ideas)
  of Discussions (reactions are already enabled there by default - upvote an existing idea instead
  of opening a duplicate one) or [open an issue](https://github.com/Zynora-fr/KubeUI/issues/new/choose)
  using the feature request template if you'd rather it be tracked like a concrete ask.

No Discord server for now - GitHub Issues/Discussions cover support without needing a separate
account or a community to moderate from day one. A Discord (or Discord-adjacent) channel is a
reasonable thing to add once there's an active enough user base that async GitHub threads stop
being enough - not promised for any particular version.

## Beta-testing a major release

Before a release that bumps the major version (see [VERSIONING.md](VERSIONING.md) for what counts),
posting a heads-up in [Discussions](https://github.com/Zynora-fr/KubeUI/discussions) ahead of
tagging it - with what changed and what to specifically try - is the plan for catching real-world
issues before they hit everyone at once. Not a formal program with sign-ups (there isn't a big
enough user base yet to justify one, per the "Pre-1.0" section of VERSIONING.md) - just: watch
Discussions/[the changelog](CHANGELOG.md) if you want to try a release early and report back.
